# Une même capacité, deux façons de l'utiliser

## Promesse confirmée par le dirigeant

Quel que soit le domaine d'application, la formation aide l'utilisateur à construire son propre agent analytics ; l'outil propose un agent prêt à utiliser.

L'offre est conçue pour être adaptable à différents domaines. Chaque version doit annoncer les cas d'usage et les sources effectivement pris en charge : la vocation transverse ne signifie pas que toutes les intégrations ou expertises métier sont déjà disponibles.

## Formation : construire son agent

Le parcours part du problème de l'apprenant et aboutit à son agent fonctionnel sur des données autorisées :

1. Définir la mission, les utilisateurs, les questions et les limites.
2. Préparer les données et contrôler leur qualité.
3. Définir métriques et dimensions dans la couche sémantique.
4. Ajouter le contexte, les sources et les règles métier.
5. Construire les outils et le comportement de l'agent.
6. Produire les réponses, rapports ou dashboards utiles.
7. Évaluer l'exactitude, les accès et les limites.
8. Mettre l'agent en service dans un environnement adapté.

Chaque étape livre un composant du projet de l'apprenant. Le résultat final est un agent exécutable, documenté et évalué, et pas seulement un cours suivi ou un notebook isolé.

## Outil : utiliser un agent déjà construit

L'utilisateur choisit un cas d'usage pris en charge, fournit ou connecte ses données, configure le vocabulaire, les métriques, le contexte et les accès, puis exécute l'agent sans devoir développer son fonctionnement.

Le produit comprend un parcours de démarrage, un exemple utilisable immédiatement sur données synthétiques, les connecteurs annoncés, des résultats vérifiables, la gestion explicite des erreurs et les limites de l'agent.

« Prêt à utiliser » autorise la configuration nécessaire, mais exige un agent fonctionnel : pas de développement à demander à l'utilisateur pour le cas d'usage annoncé. Les prérequis, éventuels comptes externes et coûts doivent être visibles.

## Socle partagé et adaptation au domaine

Formation et outil utilisent les mêmes composants versionnés : préparation des données, définitions sémantiques, contexte, outils d'analyse, logique d'agent, évaluations et artefacts.

Les éléments spécifiques au domaine sont isolés dans un profil : schéma des données, vocabulaire, KPI, règles métier, questions de référence, contraintes d'accès et formats de restitution. Ne pas coder un métier unique dans le socle.

Un exemple commercial, RH, industriel ou pédagogique illustre le socle ; il ne définit pas à lui seul le périmètre de l'offre. Une adaptation de domaine doit être vérifiée sur ses propres cas de référence.

## ACP et clustering

Ces méthodes sont disponibles comme capacités réutilisables, avec outil, exemple et formation. Les intégrer à un agent lorsque la mission le justifie ; un calcul ACP ou un clustering seul ne constitue pas un agent analytics prêt à utiliser.

## Acceptation commune

- Formation : un apprenant peut construire et exécuter son agent, puis vérifier ses réponses sur des cas connus.
- Outil : un utilisateur peut accomplir le cas d'usage annoncé après configuration, sans écrire le code de l'agent.
- Cohérence : l'exemple de formation reproduit une capacité du produit avec les mêmes contrats et définitions.
- Adaptabilité : les éléments métier sont identifiés et configurables ; documenter une seconde adaptation avant de revendiquer une généralisation démontrée.
- Qualité : sources, calculs, permissions, erreurs et limites sont examinés avant livraison.

## État

Cette page définit la cible de l'offre. Les agents produits, les formations complètes et leurs adaptations métier restent à construire et à valider.
